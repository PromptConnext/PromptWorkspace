# ISO 27001 — Policy Scope Principles

Planning guidance for an AI assistant, not legal advice.

Applies when a project must operate under (or align with) an Information
Security Management System (ISMS) certified or aligned to ISO/IEC 27001,
using the Annex A control catalogue (ISO/IEC 27001:2022) as the reference
control set.

## Data Handling & Classification

- Classify information assets (data, code, credentials, infrastructure
  config) by sensitivity and criticality (A.5.12 Classification of
  information), with handling rules per label (A.5.13 Labelling of
  information).
- Maintain an asset inventory with a named owner per asset (A.5.9
  Inventory of information and other associated assets).

## Consent & Lawful Basis

- ISO 27001 does not itself impose a consent regime, but A.5.34 (Privacy
  and protection of PII) requires identifying and complying with
  applicable data-protection law — pair this template with "GDPR" / "Thai
  PDPA" when personal data is in scope.

## Retention & Deletion

- Define retention and secure-disposal rules per asset classification
  (A.8.10 Information deletion) — deletion must be verifiable, not merely
  a soft flag.
- Apply secure media disposal/reuse controls (A.7.10 Storage media) before
  infrastructure is decommissioned or repurposed.

## Cross-Border Transfer

- Where information crosses jurisdictions (e.g. multi-region hosting,
  offshore support), apply A.5.14 (Information transfer) — document the
  transfer channel, its protection, and any applicable legal restriction.

## Security Controls — Annex A control-family mapping

- **Organizational (A.5)**: policies for information security, roles and
  responsibilities, supplier relationships, incident management.
- **People (A.6)**: screening, terms of employment, security awareness
  training, disciplinary process.
- **Physical (A.7)**: secure areas, equipment siting/protection, clear
  desk/clear screen, secure disposal.
- **Technological (A.8)**: access control (A.8.2/A.8.3), cryptography
  (A.8.24), secure development lifecycle (A.8.25-A.8.29), logging and
  monitoring (A.8.15/A.8.16), backup (A.8.13), network security
  (A.8.20-A.8.23), vulnerability management (A.8.8).
- Apply least-privilege access control (A.8.2/A.8.3) and multi-factor
  authentication for privileged access.
- Encrypt data at rest and in transit per a documented cryptographic
  policy (A.8.24).

## Audit, Logging & Breach Notification

- Centralize event logging with clock synchronization and log protection
  against tampering (A.8.15, A.8.17).
- Run continuous monitoring for anomalous activity (A.8.16) feeding a
  documented incident management process (A.5.24-A.5.28).
- Security incidents follow a defined severity/escalation path; where the
  incident involves personal data, the applicable data-protection law's
  notification window (e.g. 72 hours under GDPR/PDPA) governs timing, not
  ISO 27001 itself.

## Implications for System Design

- The system MUST maintain an asset inventory with a classification label
  and named owner per component.
- The system MUST enforce least-privilege, role-based access control with
  MFA for privileged operations.
- The system MUST encrypt data at rest and in transit per a documented
  key-management policy.
- The system MUST emit tamper-evident, centrally aggregated logs with
  synchronized timestamps.
- The system MUST support verifiable secure deletion of data and media at
  end of life.
- The system MUST integrate a vulnerability management process (scanning,
  patching SLAs) into the delivery pipeline.
- The system MUST feed a documented incident-management/escalation
  process on detected anomalies.
