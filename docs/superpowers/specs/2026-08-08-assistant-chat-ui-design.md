# Assistant chat UI — project-scoped RAG panel (apps/web)

**Date:** 2026-08-08 · **Scope:** `apps/web`, plus one additive field in `apps/cloud`.

> **Amended 2026-08-08, during planning.** This spec originally claimed zero cloud changes. Writing the plan found that `StageDocumentOut` (`apps/cloud/app/api/stage_documents.py:32-35`) returns `stage` / `content` / `updated_at` and **no `id`**, so the stage-document labeling below could not work as designed. One additive field — `id: str | None` on that response model — was approved. Everything else remains `apps/web`-only. Sections below reflect the amendment.

## Context

`apps/cloud` ships a complete project-scoped RAG assistant (ADR 0011) that no user can reach. `POST /projects/{id}/assistant/chat` (`app/api/assistant.py:186`) streams a grounded answer over SSE: it classifies the question (`content` / `lineage` / `mixed`), runs an exact graph walk for lineage questions, does membership-scoped vector search over the project's synced artifacts plus a separate code-chunk search, fetches matching code line-ranges fresh from GitHub for that request only, and emits citations. `POST /projects/{id}/assistant/reindex` backfills the embedding index. Seven cloud test files cover this path (`test_rag_chat.py`, `test_rag_lineage.py`, `test_rag_ingest.py`, `test_rag_eval.py`, `test_github_chat.py`, `test_discussion_rag.py`, `test_stage_documents_rag.py`).

`apps/web` calls none of it. Searching the web source for `assistant` returns only code comments and `ModelConnectionForm.tsx`, which lets an admin connect the chat and embedding models — for an assistant with no UI. There is no chat surface, no reindex control, and no SSE consumer for this endpoint. `apps/desktop` has no assistant references at all.

This spec adds the missing frontend. Every decision below was chosen, where a choice existed, to keep `apps/cloud` untouched — the sole exception being the additive `StageDocumentOut.id` field noted above, without which stage-document citations cannot be labeled at all.

## Decisions carried in from brainstorming

- **Slide-over panel, entered from the Discussion tab.** Not a sixth tab and not a global drawer. Discussion is where people already argue about the project, so "ask the assistant" belongs beside it. Panel state lives in `DiscussionThread`, not the project page — hoisting it would invite a global mount the panel isn't designed for (see *Graph dependency* below).
- **Answers are ephemeral.** They live in the panel for the session and vanish on close. Nothing is posted to the discussion thread. Posting an assistant answer would make it a `Discussion` row, which `app/rag/queue.py` would then embed back into the project's own corpus — so a shareable answer needs an `author_kind` field and an embed opt-out on the cloud side. Deferred deliberately, not overlooked.
- **Transcript is visible, but every request is single-turn.** `ChatRequest` is `{question: str}` (`app/models/schemas.py:626`) with no history field. The panel shows prior Q/A pairs for the session, but sends only the current question. Pronoun follow-ups ("and what about it?") will be answered blind; mitigated with composer copy asking for self-contained questions. Real multi-turn needs a `history` field, prompt-assembly changes, and token-budget accounting for the replayed turns — out of scope.
- **Citation chips are labels, not links — by choice, not by constraint.** `Citation` carries `repo` / `path` / `start_line` / `end_line` for code sources, and the schema comment (`schemas.py:615-618`) states outright that these exist so the client can link to the Git host. Linking is therefore supported and simply deferred; v1 renders the reference as text. Worth recording precisely, because "we can't link" would be false.
- **Lineage facts render as their own card, above the prose.** `LineageFacts` (`schemas.py:638-654`) is computed by a graph walk, not generated by a model. Surfacing it as a distinct card makes the exact-versus-generated boundary visible to the user, and gives the degraded budget path (below) something substantive to show.
- **SSE parsing gets a new frame-based reader.** See *The parser problem*.

## The parser problem

The assistant's stream is framed differently from the Planner's, and the existing parser is **wrong** for it — not merely incomplete.

`app/api/generation.py` emits bare `data:` deltas terminated by `event: done` or `event: error`. Its parser, `parseSseLine` in `apps/web/src/lib/planner-sse.ts`, special-cases exactly those two names and tracks state per line with no frame boundary.

`app/api/assistant.py:263-305` emits a **mid-stream named event**:

```
event: facts
data: {...}

data: {"delta":"…"}
data: {"delta":"…"}

event: citations
data: {...}
```

Fed to `parseSseLine`, this fails twice. First, `event: facts` is neither `done` nor `error`, so the function returns `prev && {...prev, fresh: false}` — with `prev` still `null` on the opening frame, it returns `null`, and the following `data:` line falls through to `event = "message"`, landing the facts payload as a text delta. Second, if that branch were widened to carry any event name, the *next* bare `data:` line would see `prev.event !== "message"` and inherit `"facts"`, turning every delta into a facts event.

The root cause is structural: the parser never resets at a frame boundary. `generation.py` never exposes this because `done` and `error` are terminal — nothing follows them.

**Resolution:** a new `apps/web/src/lib/sse.ts` implementing real SSE framing, used by the assistant only.

```ts
export type SseFrame = { event: string; data: unknown };
export function parseFrames(buffer: string): { frames: SseFrame[]; rest: string };
```

Callers accumulate decoded bytes into a buffer, call `parseFrames`, and keep `rest` for the next chunk. A frame ends at a blank line; `event` defaults to `"message"` per the SSE spec, which is what makes the reset bug structurally impossible rather than merely fixed. It handles `\r\n`, `:` comment lines, and multi-line `data:` (joined with `\n`).

`planner-sse.ts` and `useStageGeneration.ts` are **not** modified. Generalizing the existing parser in place would work, but it changes semantics under `Planner.tsx` — the most frequently edited component in the app — for no benefit to this feature. Migrating the Planner onto `lib/sse.ts` and deleting `planner-sse.ts` is a follow-up, recorded below.

### Graph dependency

`AssistantPanel` needs `ProjectGraph` to resolve citation labels. The graph is already fetched once in `app/w/[workspaceId]/p/[projectId]/page.tsx:23` and passed down to tab components, so the panel takes it as a prop and issues no second fetch. The consequence: the panel can only mount where the graph is loaded. That is fine for a Discussion-tab slide-over and would need revisiting if the panel ever goes global.

## State machine and data flow

```ts
type Turn = {
  id: number;                    // monotonic counter — display keys only, not crypto
  question: string;
  facts: LineageFacts | null;
  answer: string;                // accumulated `message` deltas
  citations: Citation[];
  status: "streaming" | "done" | "error";
  error: AssistantError | null;
};
```

`useAssistantChat(projectId)` returns `{ turns, busy, ask, reset }`.

**One request in flight at a time.** The composer is disabled while `busy`. Every request bills the workspace's daily token budget (`budget.record`, `assistant.py:291`), and concurrent asks make the budget-exhausted state arrive incoherently. `reset()` clears `turns` when the panel closes.

**Cancellation.** `ask` runs under an `AbortController`; closing the panel or unmounting aborts the read. The server keeps generating and still bills for it — the client merely stops listening. Closing the panel is not free, and the UI should not imply it is.

**Frame dispatch:**

```
event === "facts"     → turn.facts = data
event === "message"   → turn.answer += data.delta
event === "citations" → turn.citations = data.citations
default               → ignore
```

Unknown events are ignored rather than treated as errors, so a future cloud-side frame kind degrades an older tab to prose instead of breaking it.

**All operator-facing failures are pre-stream.** `400 model_connection_not_configured` (`assistant.py:200`), `429 daily_token_budget_exceeded` (`:233`), and `409 embed_model_mismatch` (`:241`) are all raised before `StreamingResponse` is constructed. They arrive as ordinary non-200 JSON with a `detail` field, never as stream events. One `!res.ok` branch handles all of them.

**Match `detail` by prefix, not equality.** The 400 and 429 details are bare identifiers, but the 409's is a full sentence built with an f-string that *begins* `embed_model_mismatch:` and goes on to name both embedding models and the reindex URL (`:243-252`). Comparing with `===` would silently fall through to the generic error branch, losing the reindex affordance — the exact case the branch exists for.

**Two distinct budget paths.** Conflating them would be a bug:

| Condition | Server behavior | Panel renders |
|---|---|---|
| Budget out, **no** facts | hard `429` before streaming | error state, "try tomorrow" |
| Budget out, **has** facts | `200`, `facts` frame, then a canned delta (`:267-282`) | fact card plus that message as ordinary prose |

The second is a **success**. The canned text flows through the `message` path like any answer and citations still arrive, so the panel needs no special case. Recorded here so nobody later "fixes" it into an error banner.

**Mid-stream death.** If `chat_provider.stream_chat` throws, the response body simply ends — no `citations` frame, no error frame. Detection: the reader completes while `status === "streaming"`. Render as `error` with "the answer was cut off", keep the partial text visible, and offer Retry.

## Rendering

### Fact card

Renders on the `facts` frame, above the prose, labeled *from the task graph* to mark it as exact rather than generated. Header is `title` plus `status`; a counts row shows `specs_total` / `tasks_total` / `tasks_done`; `task_status_counts` renders as a breakdown; `artifacts_total` and `agent_runs` (count plus any non-success status) form a footer line.

**Zero-valued fields are omitted, not printed as `0`.** A `project`-scope walk populates different fields than a `task`-scope one, and rendering every zero makes a valid card look broken.

### Citation labels

`ProjectGraph` covers only part of what citations can reference. Comparing `RAG_NODE_TYPES` (`app/rag/source.py:43`) against the web `ProjectGraph` interface (`types.ts:138`):

| Citation `node_type` | In `ProjectGraph`? | Resolution |
|---|---|---|
| `requirements` | yes | from graph |
| `spec_documents` | yes | from graph |
| `tasks` | yes | from graph |
| `discussions` | yes | from graph |
| `documents` | no | lazy `listDocuments(projectId)` |
| `stage_documents` | no | lazy `getStageDocument` × 4 stages |
| `pull_requests` | no | degraded — no web-facing list endpoint exists |

`documents` and `stage_documents` are resolved because stage documents are the constitution/specify/plan/tasks prose and will dominate citations on a planning-stage project — `stage document · 8f3a12` would otherwise be the most common chip in the panel. The fetches fire **lazily, once per panel session, only when a citation of that type actually appears**: one call for documents, and four parallel calls (one per stage) to build an id → stage-name map.

The stage-document half is what forced the cloud amendment. `GET /stage-documents/{stage}` is keyed by **stage name**, and a citation carries a row **id**, so resolving one against the other requires the response to expose its id — which it did not. Hence `StageDocumentOut.id`. `documents` needed nothing: `DocumentOut` already carries `id` and `title`.

`pull_requests` has no web-facing list endpoint, so its chips degrade to a type label plus a shortened id. The proper fix is a cloud-side batch resolver — recorded as a follow-up.

`Citation` is a **single type with a `source` discriminator** — `"vector"` (a retrieved embedding chunk), `"graph"` (a whole-node reference from the exact walk, where `chunk_index` is meaningless and always 0), or `"code"` (a fetch-on-demand code chunk carrying `repo` / `path` / `start_line` / `end_line`). There is no separate code-citation type. `CitationList` groups on `source`, rendering graph and vector citations first and code last.

Dedupe by `(node_type, node_id)`: `hits` is `top_k=8`, so the same node cited at several `chunk_index`es is common and reads as one source. Code citations render as `repo · path:start-end`. They are inert in v1 by the decision above — not because they cannot link, but because linking is deferred; ADR 0011 does mean the snippet text itself can never be expanded inline, since it was never persisted.

### Panel shell

Right-hand slide-over, roughly 400px, full-width below the `sm` breakpoint. Triggered by an `[Ask]` button in `DiscussionThread`'s header row. `Esc` closes; focus moves to the composer on open and returns to the trigger on close; `role="dialog"` with `aria-modal`; the streaming region carries `aria-live="polite"` so the answer is announced once rather than re-read on every delta.

Empty state, before the first question: one line explaining that answers are grounded in this project's synced artifacts, plus the composer placeholder asking for self-contained questions (the single-turn mitigation).

## Error handling

| `detail` | Copy | Admin action | Non-admin |
|---|---|---|---|
| `model_connection_not_configured` | "No model is connected for this workspace." | link → `/w/{ws}/settings` | "Ask a workspace admin to connect one." |
| `embed_model_mismatch` | "This project was indexed with a different embedding model." | link → `/w/{ws}/p/{id}/settings#assistant-index` | "Ask an admin to reindex it." |
| `daily_token_budget_exceeded` | "Daily assistant budget reached. Try again tomorrow." | — | — |
| other / network | raw `detail`, or "network error" | Retry | Retry |

Retry re-sends the same question rather than making the user retype it, and is offered **only** where retrying can plausibly succeed — not on 400, 409, or 429, where the blocking condition has not changed. The mid-stream cut is a fifth state: partial answer retained, a "cut off" note beneath it, Retry offered.

Non-admins get the explanatory copy but no link. `require_admin` would 403 them anyway, so offering the control would only produce a worse error.

## Reindex surface

New section in `app/w/[workspaceId]/p/[projectId]/settings/page.tsx`, anchored `#assistant-index` so the 409 copy can deep-link to it, visible to workspace admins only:

```
Assistant index                          (admins only)
Re-embeds this project's requirements, specs, tasks
and planning documents. Needed after changing the
workspace's embedding model.

  [ Reindex project ]
```

Behind a confirm step — not because it is destructive (it only enqueues `EmbedJob`s) but because it fans out one embedding call per graph node and per stage document, so a stray click on a large project spends real money.

The response is **enqueue-only**: `POST /projects/{id}/assistant/reindex` returns `{enqueued: N}` the moment jobs are queued, with no completion signal and no progress endpoint. The result renders as "N items queued for indexing." There is deliberately no spinner-until-done and no progress bar, because there is nothing to poll and such an indicator would be a lie.

## Testing

Stack is in place: vitest, happy-dom, `@testing-library/react`, `global.fetch` mocked, `vi.mock("@/lib/auth")` — the same shape as `useStageGeneration.test.ts`.

**Test-helper trap.** The existing `sseBody` helper (`useStageGeneration.test.ts:12`) joins lines with a single `\n`, which never produces a frame boundary. Copying it for the assistant would leave `parseFrames` with zero complete frames and tests that pass by asserting nothing arrived. The assistant tests need their own helper joining frames with `\n\n`, matching what `assistant.py` writes.

**`lib/sse.ts`** — pure unit tests, the highest-value tests in this change since the file exists to kill a specific bug:

- The regression case in full: `facts` frame, two `message` frames, `citations` frame — asserting the deltas come back as `message` and **not** as `facts`. This is exactly what `parseSseLine` gets wrong today.
- Chunk splits mid-frame, mid-line, and mid-UTF-8 sequence: `rest` must carry the remainder, with no frame emitted twice or dropped.
- `\r\n` endings, `:` comment lines, multi-line `data:` joined with `\n`, unknown event names passed through.
- Empty trailing buffer returns `{frames: [], rest: ""}`.

**`useAssistantChat`** — streaming accumulation into one turn; `facts` populating `turn.facts` before any prose arrives; `citations` landing at the end; each of 400 / 409 / 429 mapping to the right error, asserted on `detail`; **the soft-budget path** (200 with facts plus canned delta) resolving to `status: "done"`, not `error` — the case most likely to regress; mid-stream cut retaining partial text with `status: "error"`; abort on unmount not writing state after teardown.

**Components** — `CitationList` deduping `(node_type, node_id)` across chunk indexes, resolving labels for the four graph types, resolving `documents` and `stage_documents` after their lazy fetches, and degrading `pull_requests` to type plus short id. `FactCard` omitting zero-valued fields. Panel: `Esc` closes, focus lands on the composer, composer disabled while `busy`.

**Not covered here:** the cloud side. The seven RAG test files already cover it and this change touches no Python.

**Manual verification before calling the work done:** `pnpm --dir apps/web tsc --noEmit`, `vitest run`, and one real run against a local cloud (`uvicorn app.main:app --port 8080` with a model connection configured) — one lineage question and one content question, confirming the fact card paints before the prose and that citations resolve to real titles. Unit tests prove the framing matches this document's reading of the server; only a live run proves it matches the server.

## Out of scope

- **Multi-turn conversation.** Needs a `history` field on `ChatRequest`, prompt-assembly changes, and budget accounting for replayed turns.
- **Sharing answers into the discussion thread.** Needs `author_kind` on `Discussion` plus an embed opt-out in `app/rag/queue.py`, or assistant answers pollute the corpus they were drawn from.
- **Citation deep-linking.** Graph chips would need `selectedNodeId` threaded into `GraphBrowser` and `TaskBoard` plus a `setTab` callback out of the panel. Code chips need none of that — `repo` / `path` / `start_line` / `end_line` are already sufficient to build a Git-host blob URL, so that half is a small follow-up rather than a component change.
- **A batch node resolver** (`GET /projects/{id}/rag/nodes?ids=…`) to label `pull_requests` and replace the lazy per-type fetches.
- **Migrating `Planner.tsx` onto `lib/sse.ts`** and deleting `planner-sse.ts`.
- **Desktop.** `apps/desktop` has no assistant surface; adding one is a separate piece of work.
